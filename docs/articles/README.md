# Building Iris: a series

This is the working journal of building **Iris**, a Microsoft Teams meeting participant driven by Claude Sonnet 4.5 with a real-time photoreal avatar. Each article is a standalone field report — the decisions we made, the surprises we hit, the workarounds we landed on, and the parts we'd skip if we did it again.

The project lives at `C:\code\LiveOnTeams`. Architecture, ADRs, and the cost model are in `docs/`; the articles below pull on those as primary sources.

If you're trying to build something similar, read in order. If you're here for one specific problem, the article titles map cleanly to the symptoms.

## Articles

1. [**00 — Introduction.**](00-introduction.md) Why a Teams meeting bot with a real-time AI avatar is buildable in 2026, the architectural shape, and the roadmap for this series.
2. [**01 — Environment setup on Windows Server.**](01-environment-setup-on-windows-server.md) PowerShell 5.1 vs 7, the `python.exe` Microsoft Store stub, why we picked `uv` over pip+venv, and the validated tool list.
3. [**02 — Vendor stack selection.**](02-vendor-stack-selection.md) How we picked Claude, Deepgram, Cartesia (initially), Beyond Presence (initially), and LiveKit. Why the LiveKit "seam" is what makes the whole project rebuildable. Per-stage latency budgets.
4. [**03 — TTS swap: Cartesia to ElevenLabs.**](03-tts-swap-cartesia-to-elevenlabs.md) The Lenny's Pass detour. Why ElevenLabs Flash v2.5 over Turbo. The LiveKit Agents plugin contract that catches everyone.
5. [**04 — LiveKit Agents validation.**](04-livekit-agents-validation.md) Phase 1 going live. Connecting from RDP (broken) vs laptop (works). The Anthropic prompt-caching threshold surprise. Barge-in. The actual cost of a 6.5-minute conversation.
6. [**05 — Picking a real-time AI avatar vendor in one hour.**](avatar-vendor-ab-test.md) The Beyond Presence vs HeyGen LiveAvatar A/B test, voice held constant, in the LiveKit Agents Playground.
7. [**06 — The M365 tenant odyssey.**](06-m365-tenant-odyssey.md) M365 Family won't work; the Developer Program is no longer free; Business plans hit Error 7504; E1 is unverified; E3 is the cheapest authoritative path. The anti-fraud signup workaround. The Cloud Communications enablement gate.
8. [**07 — Cloudflare DNS and TLS.**](07-cloudflare-dns-and-tls.md) Why Cloudflare proxy must be off (gray cloud) for Graph Communications. Posh-ACME with DNS-01 challenge using a scoped Cloudflare token.
9. [**08 — The C# bot foundation.**](08-csharp-bot-foundation.md) Phase 2.1, 2.2, 2.2.5: scaffolding the .NET 8 solution, wiring `Microsoft.Graph.Communications.*` + MSAL, the `IRequestAuthenticationProvider` pattern, deploying Kestrel directly on 443, and the moment `curl https://bot.example.com/healthz` returned 200 from the public internet.
10. [**09 — Bridging audio both ways.**](09-audio-bridge-both-ways.md) Phase 2.3b + 2.3c: the "easy" half of the bridge and its three non-obvious traps — the published track must be tagged `SourceMicrophone` or the agent silently never hears it; LiveKit→Teams sends must be paced to wall-clock or playback is choppy; and the Teams→LiveKit path had a shared-buffer data race that passed every test by winning a timing race, found and fixed by reading the code adversarially at the end of the project.
11. [**10 — Bridging LiveKit video into Teams.**](10-livekit-to-teams-video-bridge.md) Phase 2.3d: why the encoded-frame passthrough we wanted didn't survive contact with the .NET LiveKit wrapper, the four-way decision recorded in ADR-009, and the FFmpeg-subprocess + Annex-B parser implementation that shipped. Three real surprises along the way: the `H264_320x180_*` format-list requirement, finding access-unit boundaries via AUD NALs, and lazy encoder spawn for variable source resolutions.
12. [**11 — Iris finally talks: Phase 2.3 end-to-end.**](11-iris-finally-talks.md) Five layers of failure peeled in the order Teams revealed them — Teams short-URL parser, `CsApplicationAccessPolicy`, JWT validator endpoint, LiveKit `SourceMicrophone` filter, and the race condition that actually mattered: `call.OnUpdated` fires on every sub-resource change (not just state transitions), so concurrent `StartAsync` invocations trampled the LiveKit `_room` field. `Interlocked.Exchange` latches in two places, an honest null-check, and the bridge holds a conversation.
13. [**12 — You can't add a calling bot to a Teams meeting.**](12-teams-add-bot-trap.md) Phase 2.4: the sideload package works but the +Add Participants search and the in-meeting Apps button both refuse to surface a calling bot, by Microsoft design. The supported workaround is the Application Instance / Resource Account pattern via `New-CsOnlineApplicationInstance` — and the free license that goes with it has a paid (or 30-day-trial) prerequisite. The pragmatic answer for dev is to keep using `/api/join`.
14. [**13 — It works: retrospective.**](13-it-works-retrospective.md) The capstone, written as the dev box is decommissioned. What we proved (buildable, ~$0.16/min, ~1–1.5 s lag), the full cost + latency breakdown, the consolidated gotcha cheat-sheet from the whole series, the two known bugs still lurking before this is production-ready (mid-call video renegotiation, unconfirmed JWT endpoint), and a cold-start runbook to redeploy the whole system onto an Azure VM — which is mostly "repoint one DNS record," because the architecture is keyed on the domain, not the host.

The research question — *is this buildable in 2026 by a small team with off-the-shelf parts?* — is answered: yes. Article 13 is the wrap-up. Future work (a production Azure deploy with the known bugs fixed, the metrics aggregator built, and the +Add UX decided) would open a second series.
